Choose Your Architecture

All three use FastAPI + PostgreSQL. The difference is in the frontend layer.

A

FastAPI + Jinja2 (Server-Rendered)

HTML pages rendered server-side. Minimal JavaScript. Closest to a traditional web app.

Pros

  • No build tools (no Node.js, no npm)
  • Simplest deployment
  • Fastest to get running

Cons

  • Limited interactivity (DRL preview, condition builder harder)
  • Page reloads for most actions
  • Hard to replicate the rich builder UI
Stack: Python · FastAPI · Jinja2 · HTMX · PostgreSQL
B

FastAPI + React (SPA) ⭐ Recommended

FastAPI serves a REST API. React handles all UI. Best for the rich condition/action builder and DRL live preview.

Pros

  • Fully interactive UI (no page reloads)
  • Easy to replicate the existing condition/action builder
  • Clear separation: API vs. UI
  • Scales well as features grow

Cons

  • Requires Node.js for build
  • Two separate servers in dev (or proxy)
Stack: Python · FastAPI · React + Vite · PostgreSQL
C

FastAPI + Vue.js (Lightweight SPA)

Same API-first approach as React but Vue is lighter, closer to the existing vanilla JS code style.

Pros

  • More approachable if team knows HTML/JS
  • Can start with CDN (no build step initially)
  • Good middle ground between options A and B

Cons

  • Smaller ecosystem than React
  • Still needs build tooling for production
Stack: Python · FastAPI · Vue 3 + Vite · PostgreSQL
