Key Workflows & API Surface

How the three main flows work end-to-end

⬆️ Workflow 1 — Import Existing DRL Files
1. Upload
User selects .drl file(s) or drops a folder. UI shows file list.
→
2. Parse
FastAPI DRL parser extracts: package, imports, functions, individual rule blocks (name / when / then).
→
3. Review
UI shows parsed rules in a preview table. User assigns to a client + confirms rule type.
→
4. Save
Confirmed rules inserted into DB with condition_raw / action_raw populated.
POST /api/import/parse → POST /api/import/confirm
📚 Workflow 2 — Browse Library & Copy Rules to Client
1. Browse
Search/filter rules across all clients by type, tool, keyword, or source client.
→
2. Preview
Click a rule to see full DRL, description, which clients use it, and history.
→
3. Copy
"Copy to Client" → picks target client, rule is duplicated and renamed (e.g. ClientCode_NS_1).
→
4. Adapt
Open copied rule in editor, adjust conditions/actions for new client's environment.
GET /api/rules?search=&tool=&rule_type=&client= → POST /api/rules/{id}/copy
📦 Workflow 3 — Create Deployment & Export DRL Bundle
1. Create
Create deployment for a client with a version tag (e.g. v1.2) and release notes.
→
2. Snapshot
All enabled rules for the client are snapshotted into deployment_rule_snapshots.
→
3. Generate
DRL Generator builds one .drl file per rule type from the snapshot. Includes package, imports, functions, rules in order.
→
4. Download
ZIP file downloaded: noise_suppression.drl, alert_classifier.drl, issue_correlation.drl, incident_rules.drl, recommendation.drl
POST /api/deployments → GET /api/deployments/{id}/export → .zip download
